## 附录 A：发布清单（docs-release 维护）

### A.1 发布脚本

`scripts/release.mjs`（Node ESM，零依赖，Windows 友好），一行命令：

```
node scripts/release.mjs
```

执行顺序与要点：

1. **版本唯一来源**：只读 `package.json.version`，脚本里不写死版本号；`package.json` 缺少 `version` 直接失败；
2. **必需文件校验**：按 `package.json.files` + `package.json` 自身展开（支持 `*` / `?` 段通配，例如 `locale/*.json`），任一模式匹配不到文件即失败；
3. **语法检查**：对所有 `.js` 待打包文件跑 `node --check`（`index.js`、`client.js`），失败即中止；
4. **staging**：清空并重建 `%TEMP%\pw-pkg-<版本>\personal-workbench\`，按 files 列表保留相对目录复制；
5. **zip**：`powershell -NoProfile -NonInteractive -Command Compress-Archive -LiteralPath <staging> -DestinationPath <out> -Force`，产物 `E:\deepseek\personal-workbench-<版本>.zip`；zip 内根目录是 `personal-workbench\`，与 README「方式三：压缩包安装」描述的「解压后选择 personal-workbench 文件夹」一致；
6. **tgz**：用 Harness 自带 node（`…\dependencies\node\bin\node.exe`）执行 `…\dependencies\pnpm\bin\pnpm.mjs pack --pack-destination .`（cwd = staging）。**pnpm 11.28 的 `pack` 子命令不接受 `--offline` 参数**（`Unknown option: 'offline'`），脚本改为注入 `npm_config_offline=true` / `npm_config_prefer_offline=true` 达成同样的离线效果；产物 `local-personal-workbench-<版本>.tgz` 重命名为 `E:\deepseek\personal-workbench-<版本>.tgz`；
7. **一致性校验**：用 `Expand-Archive` 解压 zip 到临时目录，逐文件与工作区同名文件比对 SHA-256，打印 `MATCH` / `DIFF`（含「包内有工作区没有」「工作区有包内缺失」两类差异），有 DIFF 时以非 0 退出码结束；
8. **重名产物**：先备份为 `<名字>.reset`；`.reset` 已被占用且内容不同则用 `.reset-2`、`.reset-3`…（绝不覆盖旧备份）；已有备份与待备份内容完全一致时跳过，避免重复堆文件；
9. 可选环境变量：`PBW_RELEASE_OUT`（默认 `E:\deepseek`）、`PBW_PNPM`、`PBW_PNPM_NODE`、`PBW_KEEP_STAGING=1`（保留 staging 与校验目录便于排查）。

脚本不联网、不碰 Git、不启停插件，只写 `%TEMP%\pw-pkg-*` 与输出目录。
