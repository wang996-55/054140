# 个人工作台（Personal Workbench）

DeepSeek Harness 的本地插件：给 Harness 增加一个「工作台」侧栏面板，包含：

- **概览**：问候、数据卡片、最近生成画廊、快捷入口
- **生图**：电商模特图工作间（模特/背景/自定义提示词只能从「提示词库」点选、生图页不显示提示词全文也不提供输入框，只以按钮形式展示已保存的提示词，点按钮即加载该条，按钮上只显示条目名（悬停也不会显示全文），再点一次取消；旧版本手打过的提示词会在首次加载时自动转入提示词库，模板里的提示词随库内修改/删除同步，字段里出现库中不存在的提示词会标黄并给出「存入库」与「清除」；模特展示固定为「从脖子处裁切」的构图约束（以单段 JSON 覆盖写入提示词开头，列出必定出现/必定不会出现的部位）、商品参考图、多接口配置、1K / 2K / 4K 分辨率、画幅与分辨率决定请求尺寸（提示词里不再写像素尺寸）、商品保真（V2.4 · 整段 JSON）：原有重复描述已合并；V2.4 放宽了手部遮挡（允许手插兜等自然姿态遮挡局部结构）并新增参考图顺序约定（第 1 张视为正面主图）；旧版保存过且未编辑过的副本会自动升级到 V2.4（逐字比对，不覆盖自定义过的内容），显示「已自定义」时也可点「默认」恢复；设置里可编辑，保存时校验 JSON）、多并发生成队列、更换商品参考图后 5 秒自动提取商品描述（识别模型带「商品细节严格锁定」12 项规则，识别结果以 JSON 键值格式填入商品描述并进入提示词，商品描述自动前置「商品款式以参考图为唯一权威、动作 / 背景 / 光线描述照常生效」声明））；图片请求默认使用**流式响应**（SSE，边生成边接收；可在设置里切换非流式，接口不支持流式时自动回退）；接口把参考图原样返回时自动重试并拒绝保存假结果
- **尺码表**：上传尺码表图片自动识别，生成带品牌 Logo、建议身高/体重（kg/斤可切换）的尺码表海报，可下载 PNG
- **本地持久化**：商品参考图、品牌 Logo、尺码表数据等保存在本机，刷新/重启后继续可用，只有手动删除/替换才会清除
- **打开输出目录**：会优先尝试聚焦已打开的同目录窗口（最小化/隐藏的也会先恢复显示）；如果系统不允许聚焦（部分 Windows 环境，或窗口被其它程序抢占），会改为新开一个窗口，不会丢失目录
- **设置**：多接口配置与切换、图片请求类型（流式/非流式）、模型一键拉取（生图接口与视觉接口都支持）、输出目录、商品图识别视觉模型（Harness 内置模型为默认，可添加多个第三方 OpenAI 兼容视觉接口并自由切换）、内置提示词编辑（保真规则为 JSON，保存时校验合法性）、外观强调色
- 模板库、提示词库、动作库等可复用内容（提示词库是可复用提示词的唯一创建/编辑入口，编辑直接在该条上展开；未保存的编辑不会因为返回生图页或切换标签而丢失，同一类别下不允许重复内容；提示词库支持**一键导出 / 导入**——导出把整个库存成一个 JSON 文件，换电脑或另一个 Harness 时用「导入」加回来，同类别同内容的条目自动跳过；动作库同样支持**一键导出 / 导入**，并可按正面 / 侧面 / 背面分组归类）

插件不修改 Harness 核心，可在「插件」页随时启停或卸载。

## 安装要求

- DeepSeek Harness 桌面版（Web UI / profile 模式），建议版本不低于 `0.2.1-rc.2`；
- 需要 Harness 自带的 `llm`、`attachments` 服务（用于「从商品图提取」「尺码表识别」等视觉功能）。缺少时其他功能仍可用。

## 安装方式（任选其一）

### 方式一：本地目录安装（推荐，最简单）

1. 把本项目文件夹放到任意位置，例如 `D:\plugins\personal-workbench`（文件夹内应有 `package.json`）；
2. 打开 Harness → 左侧「插件」页；
3. 点「添加插件」→ 选择「安装第三方插件」；
4. 在包名输入框粘贴项目文件夹的**绝对路径**（例如 `D:\plugins\personal-workbench`）；
5. 勾选信任提示，点「安装」，等待完成后启用；
6. 刷新页面（Ctrl+R），左侧栏出现「工作台」图标。

> 本地目录安装会以链接方式引用该文件夹，移动或删除文件夹会导致插件失效。

### 方式二：Git 地址安装

如果代码放在 GitHub/Gitee：

1. 在 Harness「插件」页 →「添加插件」→「安装第三方插件」；
2. 粘贴仓库地址，例如 `https://github.com/你的账号/personal-workbench.git`；
3. 安装并启用。

### 方式三：压缩包安装

1. 解压收到的插件压缩包（文件名形如 `personal-workbench-<版本号>.zip`，版本号以实际收到为准）；
2. 按「方式一」选择解压后的 `personal-workbench` 文件夹安装。

## 首次使用

1. 打开「工作台 → 设置」，填写你的图片接口地址（OpenAI 兼容）与 API Key，点「测试连接」后保存；可配置多个接口并备注名称；
2. 回到「生图」页：先在「提示词库」创建模特 / 背景 / 风格提示词，再回到生图页对应字段点选；上传商品参考图，选择画幅与分辨率，点「✦ 生成图片」；提示词是怎么拼出来的、默认画幅与保真规则有哪些约定，见下面的「生图提示词构成」；
3. 图片保存在设置里的输出目录；生成任务支持并发排队；
4. 「尺码表」页可上传现有尺码表截图自动识别，上传品牌 Logo 后生成海报并下载 PNG；
5. 「动作库」按**正面 / 侧面 / 背面**分组管理动作（生图页「姿态」的 chips 也按同样分组排列，空组不显示），**朝向由标题自动判断**：标题里写了「正面 / 侧面 / 背面」（或「背对镜头」「侧身」这类说法）就归到对应分组，改标题即换组；标题没写方向时才需要手动选，旧数据也会按标题自动重新归组；页面顶部是「导入 / 导出 / ＋ 新建动作」，点「新建动作」才展开编辑区，每行的「编辑」是原地展开、不再跳转。导入 / 导出是一个 JSON 文件，可以在另一台电脑上复用，重复的动作会自动跳过。**标题不用手打**：留空保存会自动生成一个标题，也可以随时点「自动生成标题」重新生成，最长 15 个字（提示词库的编辑区同样支持）。如果描述里本身就写了名字（例如从别的工具粘过来的 `"动作名称": "正面微侧身持手机自然站姿"`），会直接提取这个字段当标题，不再让模型改写。

API Key 只保存在本机 Harness profile 目录，不会发送到浏览器；插件包本身不含任何密钥或用户数据。

## 生图提示词构成

生图提示词由「一段散文 + 两段可编辑 JSON」拼成：开头是取景 JSON，中间是描述 / 姿态 / 背景等散文，末尾必要时再重申一次构图硬性要求；开启严格保真时追加保真 JSON。下面这些规则是为了让各部分不再互相打架（例如构图要求裁掉头部、保真规则却要求参考图里的手不能挡）。

- **模特只有文字描述，没有模特 / 场景参考图**：工作室里能上传的参考图只有商品图；模特由「模特提示词」这段文字描述，背景由「背景提示词」描述。因此提示词里不会出现「以模特参考图中的同一模特为原型」这类句子（该分支已删除，避免暗示一个并不存在的上传项）。
- **描述前缀只在有商品参考图时出现**：上传商品图后，描述开头的前缀只声明「商品款式（颜色、面料、结构与版型）以参考图为唯一权威依据」，并明确保留「模特动作、背景环境与光线等描述照常生效」；没上传商品图时不会追加这段前缀。
- **严格保真只在有商品参考图时生效**：没有上传商品图就不会追加保真 JSON，避免提示词声称「以商品参考图为唯一依据」却根本没有图。
- **手部遮挡**：保真规则只禁止「大面积遮挡 / 刻意捂挡」（例如用上衣、手袋遮住关键结构），并显式允许手插兜、手扶裤缝、手拿手机这类自然姿态造成的局部遮挡，所以动作库里的插兜动作不会和保真规则打架（旧版保存过且**未编辑过**的保真规则会自动升级到 V2.4；显示「已自定义」的不会被覆盖，点「默认」可恢复为内置版本）。
- **取景与构图**：选「从脖子处裁切」时，比例文案是「颈部以下取景」；取景 JSON 里带一条「人物占比：颈部到裤脚占满画面高度，画面顶部不留多余空间」，提示词末尾还会硬性重申一次（头部与面部不进画面）。
- **默认画幅是竖版 3:4**：方形装不下「颈部到脚」，会逼模型缩小人物、又把头顶带回来；需要方形可以手动切换。
- **镜头句按需切换**：默认 `f/5.6`（主体全程清晰，面料纹理与缝线可辨）；只有在「补充描述」或「背景」里写了浅景深 / 虚化 / bokeh，才切到 `f/2.8`（主体清晰、背景柔和虚化）。
- **不写像素尺寸**：提示词里不再出现「成图尺寸 1152×2048 像素」这类句子，实际尺寸由请求参数（画幅 + 分辨率）决定。
- **同一条约束不重复**：「商品颜色、材质、版型与结构以商品参考图为准」这句只在保真模块关闭（或没有商品参考图）时才追加，开启保真时由保真 JSON 表达同一约束。
- **多张商品参考图的顺序**：按上传顺序解读——第 1 张视为正面主图，其后依次是侧面、背面与细节图；角色无法判断时以第 1 张为准。
- **负向词默认关闭**：开启后默认负向词用「叠加文字与水印」而不是裸「文字」（街头招牌本来就带文字），并且去掉了「五官扭曲」（无脸构图里没有这个对象）；需要时在设置里手动开启。
- **语言跟随界面**：Harness 语言为英文时散文段出英文；内置的取景 JSON 与保真 JSON 仍是中文（它们属于可在设置里编辑的内容），见「已知限制」。

## 数据存放位置

下文的 `<Harness profile>` 指 Harness 的配置目录：默认是 `%USERPROFILE%\.dsh`，如果设置了 `DSH_PROFILE_DIR` 环境变量，则以该变量的值为准。

| 内容 | 位置 | 清理方式 |
| --- | --- | --- |
| 接口配置与 API Key（含第三方视觉接口） | `<Harness profile>\personal-workbench\settings.json`；每次成功保存时，上一版会备份到同目录的 `settings.json.bak` | 关闭插件后删除这两个文件，重启 Harness 即回到默认配置（需要重新填接口与 Key） |
| 已保存的参考图（商品参考图、品牌 Logo） | `<Harness profile>\personal-workbench\refs\` | 在工作台里替换或删除对应图片；也可以直接删除该目录下的文件（旧版本留下的模特图 / 背景图文件同样在这里，可一并删除） |
| 生成的图片 | 「设置 → 输出目录」指向的文件夹，默认 `%USERPROFILE%\Pictures\DSH-Workbench` | 直接在资源管理器里删除；同目录下的 `.workbench-meta` 只是图片的元数据，可以一并删除 |
| 尺码海报保存目录（用户自选，默认浏览器下载目录） | 在「尺码表 → 下载 PNG」上方的「保存目录」里选择的文件夹；不填则走浏览器默认下载 | 不再需要时点「恢复默认下载」清空设置；已经写进该目录的海报直接在资源管理器里删除 |
| 浏览器侧偏好：表单草稿、提示词库、动作库、模板库、强调色、保真规则、尺码表与海报设置、尺码海报保存目录 | 当前浏览器的 localStorage，键名以 `pbw.` 开头：`pbw.form.v1`、`pbw.prompts.v1`、`pbw.poses.v1`、`pbw.templates.v1`、`pbw.accent.v1`、`pbw.fidelity.v1`、`pbw.sizeposter.v1`、`pbw.posterdir.v1`（只存目录路径；`pbw.sizetable.v1` 是早期版本遗留键，新版不再写入，可直接删除）；条目名称（标题）随动作 / 提示词一起保存在原处，无需单独迁移 | 按 F12 打开开发者工具 → Application（应用）→ Local Storage，删除这些 `pbw.` 开头的键；或清空该站点的数据（会同时清掉 Harness 其他前端缓存） |

- **尺码海报的「保存目录」是怎么回事**：在「尺码表 → 下载 PNG」上方点「选择」挑一个文件夹（也可以手填路径），之后「下载 PNG」会直接保存到该目录并提示完整路径；不填则保持浏览器默认下载，点「恢复默认下载」清空。这一步属于**本机文件写入**：海报由 Host 侧写盘，API Key 仍然只在 Host 侧、不进浏览器；目录必须已存在（不存在会报 `dir-not-found`），同名文件会自动加 `-1`、`-2` 后缀，不会覆盖旧文件。

换电脑或重装时的迁移方式：

- **配置与参考图**：把 `<Harness profile>\personal-workbench\` 整个目录复制到新环境的同名位置即可；
- **提示词库 / 模板库**：在「提示词库」点「导出」得到 `prompts-YYYY-MM-DD.json`，到新环境点「导入」（同类别同内容会自动跳过）；
- **动作库**：在「动作库」页面顶部点「导出」得到一个动作 JSON 文件，到新环境点「导入」即可，重复动作会自动跳过；
- **已生成的图片与尺码海报**：属于输出结果，按需单独拷贝对应目录，不需要迁移。

## 安全说明

- **API Key 是明文保存的**：接口配置（含 API Key）以明文写在 `<Harness profile>\personal-workbench\settings.json` 里；同目录的 `settings.json.bak` 是上一版备份，**同样包含 Key**。这两个文件请按密钥对待：不要提交到 Git、不要随截图或压缩包分享。`settings.json.bak` 建议定期清理（直接删除即可，下次保存会重新生成）。
- **Key 不会进入浏览器**：Key 只在 Host 侧（Harness 的 Node 进程）用于请求接口。页面通过 `/api/personal-workbench/*` 拿到的配置是脱敏版本，只有「是否已设置 Key」这类标记，没有 Key 本身；插件包（`client.js`）里也不含任何密钥或用户数据。
- **本地 HTTP 路由做了同源与防 DNS rebinding 校验**：所有 `/api/personal-workbench/*` 路由都会校验请求的 `Host` 以及 `Origin`/`Referer`，只接受本机或 Harness 自己公布的地址，用来挡 CSRF 与 DNS rebinding。因此不要用反向代理改写 `Host` 把它暴露到局域网或公网，也不要从其他站点用脚本直接调用这些路由。
- **同源校验的范围**：所有 `/api/personal-workbench/*` 请求都会做精确的 origin 比对——协议、主机、端口三者必须与 Harness 上报的地址完全一致；`localhost`、`127.0.0.1`、`[::1]` 视为同一台机器的别名，但必须同协议、同端口。因此本机其它端口的页面（例如 `localhost:3000` 的本地开发站）**无法**调用本插件接口；同理 `https://127.0.0.1:58074` 与 `http://127.0.0.1:58074` 也互不通用。不带 `Origin`/`Referer` 的命令行调用仍被允许（便于本机脚本），但请求的 `Host` 同样必须是本机地址。
- **用户数据都在本机**：参考图存在 `<Harness profile>\personal-workbench\refs\`，生成图存在设置里的输出目录。请按个人资料对待，共享电脑上用完记得清理（见上面的表格）。
- **尺码海报会写到你自己选的目录**：设置「保存目录」后，「下载 PNG」由 Host 侧把文件直接写到该文件夹（目录必须已存在，且当前账号有写权限）。文件名固定在 `size-chart*.png` 白名单内，同名会自动加 `-1`、`-2` 后缀，不会覆盖已有文件；不设置则仍走浏览器默认下载。该目录路径只保存在浏览器本地（`pbw.posterdir.v1`），不会上传到任何地方。
- **自动生成标题只发送你写的描述文本**：生成标题时只把描述里的文字部分发给「本机 Harness 配置的默认文本模型」，不包含参考图、不包含 API Key，也不占用你在「设置」里填的图片接口额度；模型不可用、被限流或返回聊天式无关内容时，会自动回落为本地按描述截取的标题，保存照常成功、不会阻塞。
- **安装方式本身的风险**：本地目录安装走的是本机符号链接，指向的文件夹如果被其他程序改写，插件下次加载就会执行被改动的代码；规避办法见「已知限制」。

## 更新

- **本地目录安装**：用新版文件覆盖原来的 `personal-workbench` 文件夹，然后在「插件」页把本插件关闭再启用（或重启 Harness），刷新页面即可；
- **Tarball / Git 安装**：在「插件」页卸载旧版，再按上面的方式安装新版。

## 常见问题

- **图片请求默认是流式响应**：工作台现在按「流式（SSE）」发起生图请求，边生成边接收，长耗时接口更稳。接口明确不支持流式（返回 unsupported / invalid stream）或返回无法识别的流时，会自动回退一次非流式请求；也可以在「设置 → 请求类型」里固定为「非流式响应」。
- **设置文件损坏 / 保存失败**：`settings.json` 无法解析时会优先从同目录的 `settings.json.bak` 自动恢复；如果连备份也不可用，工作台会保留原文件、给出提示并暂停保存，避免用默认配置覆盖掉接口和 Key。修复或恢复文件后重新打开工作台即可继续保存。
- **接口账户余额不足（insufficient balance）**：中转接口的账户余额/额度用完了。表现为单个任务还能偶尔成功、多并发时其余任务立刻失败。工作台会显示「余额不足」提示并停止剩余排队任务，避免整队报错；请到对应平台充值，或在「设置」里更换接口/模型。
- **多并发时偶发失败**：接口上游 5xx/429/超时/网络错误现在会自动重试一次；余额/鉴权类错误不重试并立即停止队列。
- **商品图提取想用第三方视觉模型**：「设置 → 商品图识别模型」里 Harness 内置模型是默认项，可添加多个第三方 OpenAI 兼容视觉接口（接口地址含 `/v1`、支持图片输入的模型名、API Key），点卡片即可自由切换；商品图提取和尺码表识别都会使用当前选中的接口。Key 只保存在本机配置里，不会回传浏览器。
- **换电脑 / 重装后恢复提示词**：打开「工作台 → 提示词库」，点右上角「导出」得到 `prompts-YYYY-MM-DD.json`；在新环境里点「导入」选择该文件即可。已存在的同类别同内容条目会自动跳过，不会产生重复；文件里没有提示词、格式不对或全是重复时，页面会直接说明原因。
- **生成结果就是自己上传的商品图**：个别中转接口在处理图片编辑请求失败时，会用「原样返回参考图」冒充成功。工作台从 1.1.2 起会自动识别这种返回：先自动重试一次，成功则正常保存；仍失败则报错且不保存假图。若反复出现，请在「设置」里更换接口或模型（例如 `gpt-image-2.5-flare`、`gpt-image-2`、`nano-banana-2.1-2k`）。

## 错误提示与重试

- **错误提示带错误码**：失败提示除了中文原因，还会带一个固定的错误码，便于排查和反馈，例如 `provider-balance`（接口账户余额/额度不足）、`provider-rate-limit`（上游限流 / 429 / 请求过于频繁）、`provider-timeout`（接口响应超时）、`prompt-too-long`（提示词超过字符上限）、`body-too-large`（上传的参考图或请求体超过接口大小上限）、`reference-count`（参考图张数超过上限）、`reveal-outside-output-dir`（只能打开输出目录及其子目录）、`missing-dir`（没有选择尺码海报的保存目录）、`missing-image`（海报内容为空）、`dir-not-found`（保存目录不存在）。反馈问题时带上错误码，定位会快很多。完整错误码表见 `docs/audit-2026-10-20.md` 附录 B。
- **失败任务可以重试**：队列里失败的任务不用重新上传参考图或重新点选提示词，直接在队列里对这条任务点重试即可重新提交，其余已完成的结果不受影响。
- **网关异常会被识别**：部分中转接口会用 HTTP 200 返回一段 HTML 错误页或 JSON 报错，而不是图片。工作台会按图片字节特征校验返回内容，这类「返回 200 但内容不是图片」的响应会被判为失败并说明原因，不会存成假图；原样返回参考图冒充成功的响应同样会被识别，并先自动重试一次。
- **什么时候不重试**：余额、鉴权类错误不重试，并会立即停止剩余排队任务；上游 5xx、429、超时与网络错误会自动重试一次（详见「常见问题」）。

## 已知限制

- **多标签页同时改设置时「后保存者胜」**：两个标签页各自保存时，后保存的那份会整体覆盖先保存的配置（包括接口与 Key）。规避：同一时间只在一个标签页里改设置，改完刷新其他标签页再操作。
- **写盘没有 fsync**：配置保存后如果立刻断电或系统崩溃，极端情况下可能丢掉最后一次修改。规避：改完重要配置后等一两秒再关机/休眠，重新打开工作台确认一次设置还在。
- **「打开输出目录」在部分 Windows 环境不会聚焦已开的窗口**：这个功能依赖前台窗口权限与 PowerShell/COM 是否可用，在前台锁定、组策略限制等环境下会退化成新开一个资源管理器窗口。规避：这只是回退行为，不影响文件本身；想固定用同一个窗口时手动打开一次该目录即可。
- **本机符号链接安装存在本机攻击面**：本地目录安装是以链接方式引用项目文件夹，能改写该文件夹的本机进程或账号就有机会影响插件下次加载时执行的代码。规避：把项目放在只有你有写权限的目录（不要放共享盘、公共目录或临时目录），定期检查该目录有没有异常改动。
- **拿不到 Web GUI 访问地址时，所有带 Origin 的请求都会被拒绝**：插件启动时如果读不到 Harness Web GUI 的实际地址（`webServer.getOrigin()` 与广告地址都不可用），出于防跨站与防 DNS rebinding 的考虑，会拒绝所有带 `Origin` 的请求，表现为整页报错、无法生图。规避：确认 Harness 的 Web GUI 地址能被插件读取（正常从 `http://127.0.0.1:58074` 打开即可）；如果使用了反向代理或 TLS 终止，请让 Harness 上报外部可见的地址，否则插件会保持拒绝——启动日志里可以看到一条「未能获取 Web GUI 的 Origin…」的告警。
- **自动生成的标题可能概括不准**：标题是由文本模型对描述做概括，描述里既有场景又有动作时容易偏向其中一个（例如更强调场景而不是动作）。规避：点「自动生成标题」多试一次，或者直接在输入框里手动改成你要的标题；另外标题最长 15 个字，超长内容会被截断。
- **英文界面下内置的两段 JSON 仍是中文**：散文段会跟随界面语言出英文，但内置的取景 JSON 与保真 JSON 保持中文——它们是可以在「设置」里编辑的文本内容，而不是界面文案。规避：英文界面里如果想全英文，可在设置里把这两段 JSON 自行改成英文再保存（保存时会校验 JSON 合法性）；纯中文界面不受影响。
- **颈部裁切只能靠提示词约束，生成模型不保证 100% 服从**：插件会把「颈部以下取景」「画面顶部不留多余空间」写进取景 JSON，并在提示词末尾再硬性重申一次，但最终仍取决于模型是否照做；换模型、换接口或降低并发后重试通常更稳。若反复出现头部，下一步考虑成图后处理（暂未实现）。
